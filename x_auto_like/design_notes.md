# X 自動いいねシステム 設計メモ

## 2026年2月時点のX API 最新状況

### 料金体系（2026年2月以降）
- **Free tier**: いいね（POST /2/users/:id/likes）エンドポイントは2025年8月から廃止
- **Pay-per-use（新規デフォルト）**: クレジット購入制
  - いいね（User Interaction: Create）: $0.015/リクエスト
  - 投稿読み取り（Post: Read）: $0.005/リソース
  - ユーザー読み取り（User: Read）: $0.010/リソース
- **Basic（既存加入者のみ）**: $200/月
- **Pro（既存加入者のみ）**: $5,000/月

### レートリミット（いいね）
- POST /2/users/:id/likes: 50回/15分、1,000回/24時間（Per User）

### 重要事項
- 新規開発者は Pay-per-use のみ選択可能（Basic/Proへの新規加入不可）
- いいねは "User Interaction: Create" として $0.015/リクエスト
- Free tierではいいねエンドポイント使用不可

## コスト試算（300アカウント対象、15分ごとチェック）

### 読み取りコスト
- 15分ごとに300アカウントのタイムラインを確認
- 1回のチェックで最大300アカウント × 最新ツイート数件 = 約300〜900リソース
- 1日: 96チェック × 300アカウント = 28,800〜86,400リソース
- 月間: 約864,000〜2,592,000リソース × $0.005 = $4,320〜$12,960/月

→ **コスト最適化が必須**

### 最適化戦略: ユーザータイムライン取得の効率化
- `GET /2/users/:id/tweets` を使い、since_id パラメータで差分取得
- 1アカウントあたり1リクエスト（最新ツイートのみ取得）
- 300アカウント × 96チェック/日 = 28,800リクエスト/日
- 取得ツイート数を最小化（max_results=5）
- 重複排除（24時間ウィンドウ内の同一リソースは課金なし）

### いいねコスト
- 1日平均いいね数を仮定（300アカウント × 平均2投稿/日 = 600いいね）
- 月間: 18,000いいね × $0.015 = $270/月

### 現実的な月間コスト試算
- 読み取り（最適化後）: 300アカウント × 5ツイート × 96チェック × $0.005 = $720/月
- いいね: 600/日 × 30日 × $0.015 = $270/月
- **合計: 約$990/月**

→ **重要**: 対象アカウント数・チェック頻度・取得ツイート数の絞り込みが費用に直結

## アーキテクチャ設計

### 採用方針
1. X API v2 (OAuth 2.0 User Context) を使用
2. tweepy ライブラリ（Python）
3. SQLite でいいね済みツイートIDを管理（重複いいね防止）
4. systemd + cron で15分ごとに実行
5. ログローテーション対応

### ファイル構成
```
x_auto_like/
├── config.yaml          # 対象アカウントリスト・API認証情報
├── auto_like.py         # メインスクリプト
├── requirements.txt     # 依存パッケージ
├── liked_tweets.db      # SQLite（いいね済みID管理）
├── logs/
│   └── auto_like.log    # 実行ログ
└── setup.sh             # 初期セットアップスクリプト
```

### 凍結対策
1. レートリミット厳守（50回/15分 → 余裕を持って40回/15分以内）
2. いいね間に 2〜5秒のランダムスリープ
3. 1回の実行でいいね上限を設定（例: 30いいね/実行）
4. 重複いいね完全防止（SQLiteで管理）
5. エラー時の指数バックオフ
6. ログによる異常検知
